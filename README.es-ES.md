# Serverless M

![splash.gif](https://raw.githubusercontent.com/aa2kb/serverless-modular/master/images/splash-1.gif)

Serverless M (o Serverless Modular) es un complemento para el [serverless framework](https://serverless.com/). Este complemento te ayuda a gestionar múltiples proyectos serverless con un solo archivo serverless.yml. Te ofrece opciones de CLI súper potentes que puedes usar para crear nuevas características, compilarlas en un solo archivo e implementarlas todas en paralelo.

Actualmente, este complemento solo ha sido probado para el siguiente stack:

* AWS
* NodeJS λ
* Rest API (También puedes usar otros eventos)

## Prerrequisitos

Asegúrate de tener instalado el CLI de serverless.

```yml
# Instalar serverless globalmente
$ npm install serverless -g
```

## Para comenzar

Para iniciar el proyecto serverless modular localmente, puedes comenzar con las plantillas es5 o es6 o agregarlo como un complemento.

### Instalación de la plantilla ES6

```yml
# Paso 1. Descargar la plantilla
$ sls create --template-url https://github.com/aa2kb/serverless-modular/tree/master/template/modular-es6 --path myModularService

# Paso 2. Cambiar directorio
$ cd myModularService

# Paso 3. Crear un archivo package.json
$ npm init

# Paso 3. Instalar dependencias
$ npm i serverless-modular serverless-webpack webpack --save-dev
```

### Instalación de la plantilla ES5

```yml
# Paso 1. Descargar la plantilla
$ sls create --template-url https://github.com/aa2kb/serverless-modular/tree/master/template/modular-es5 --path myModularService

# Paso 2. Cambiar directorio
$ cd myModularService

# Paso 3. Crear un archivo package.json
$ npm init

# Paso 3. Instalar dependencias
$ npm i serverless-modular --save-dev
```

Si no deseas usar las plantillas anteriores, simplemente puedes agregarlo en tu proyecto existente.

### Agregar como complemento

```yml
plugins:
  - serverless-modular
```

Ahora ya estás listo para comenzar a construir tus funciones serverless modulares.

## Referencia de la API

El CLI de serverless se puede acceder mediante:

```yml
# CLI de Serverless Modular
$ serverless modular

# abreviatura
$ sls m
```

El CLI de Serverless Modular se basa en 4 comandos principales:

* `sls m init`
* `sls m feature`
* `sls m function`
* `sls m build`
* `sls m deploy`

### Comando init

```yml
sls m init
```

El comando init de serverless ayuda a crear un `.gitignore` básico que es útil para serverless modular.

El `.gitignore` básico para serverless modular se ve así:

```yml
#node_modules
node_modules

#sm main functions
sm.functions.yml

#serverless file generated by build
src/**/serverless.yml

#main serverless directories generated for sls deploy
.serverless

#feature serverless directories generated sls deploy
src/**/.serverless

#serverless logs file generated for main sls deploy
.sm.log

#serverless logs file generated for feature sls deploy
src/**/.sm.log

#Webpack config copied in each feature
src/**/webpack.config.js
```

### Comando feature

El comando feature ayuda a crear nuevas características para tu proyecto.

#### Opciones (Comando feature)

Este comando viene con tres opciones:

**--name**: Especifica el nombre que deseas para tu característica.

**--remove**: Establece el valor en true si deseas eliminar la característica.

**--basePath**: Especifica la ruta base que deseas para tu característica, esta ruta base debe ser única para todas las características. _ayuda a ejecutar en línea con el [offline plugin](https://github.com/dherault/serverless-offline/issues) y para [API Gateway](https://aws.amazon.com/api-gateway/)_.

| Opciones      | Atajo   |  Requerido  |      Valores    |     Valor predeterminado   |
| ------------- | :-----: | :---------: | -------------- | -------------------------- |
| --name        |    -n   |     ✅      | _string_       | N/A                        |
| --remove      |    -r   |     ❎      | _true, false_  | false                      |
| --basePath    |    -p   |     ❎      | _string_       | igual que el nombre        |

#### Ejemplos (Comando feature)

##### Crear una característica básica

```yml
# Creando una característica jedi
$ sls m feature -n jedi
```

##### Crear una característica con una ruta base diferente

```yml
# Una característica con una ruta base diferente
$ sls m feature -n jedi -p tatooine
```

##### Eliminar una característica

```yml
# Anakin va a eliminar la característica jedi
$ sls m feature -n jedi -r true
```

### Comando function

El comando function ayuda a agregar nuevas funciones a una característica.

#### Opciones (Comando function)

Este comando viene con cuatro opciones:

**--name**: Especifica el nombre que deseas para tu función.

**--feature**: Especifica el nombre de la característica existente.

**--path**: Especifica la ruta para el punto final HTTP _ayuda a ejecutar en línea con el [offline plugin](https://github.com/dherault/serverless-offline/issues) y para [API Gateway](https://aws.amazon.com/api-gateway/)_.

**--method**: Especifica el método HTTP _ayuda a ejecutar en línea con el [offline plugin](https://github.com/dherault/serverless-offline/issues) y para [API Gateway](https://aws.amazon.com/api-gateway/)_.

| Opciones      | Atajo   |  Requerido  |      Valores    |     Valor predeterminado   |
| ------------- | :-----: | :---------: | -------------- | -------------------------- |
| --name        |    -n   |     ✅      | _string_       | N/A                        |
| --feature     |    -f   |     ✅      | _string_       | N/A                        |
| --path        |    -p   |     ❎      | _string_       | igual que el nombre        |
| --method      |    -m   |     ❎      | _string_       | 'GET'                      |

#### Ejemplos (Comando function)

##### Crear una función básica

```yml
# Creando una función cloak para la característica jedi
$ sls m function -n cloak -f jedi
```

##### Crear una función básica con una ruta y método diferentes

```yml
# Creando una función cloak para la característica jedi con ruta y método HTTP personalizados
$ sls m function -n cloak -f jedi -p powers -m POST
```

### Comando build

El comando build ayuda a compilar el proyecto para ámbito local o global.

#### Opciones (Comando build)

Este comando viene con cuatro opciones:

**--scope**: Especifica el ámbito de la compilación, úsalo junto con la etiqueta "--feature".

**--feature**: Especifica el nombre de la característica existente que deseas compilar.

| Opciones      | Atajo   |  Requerido  |      Valores    |     Valor predeterminado   |
| ------------- | :-----: | :---------: | -------------- | -------------------------- |
| --scope       |    -s   |     ❎      | _string_       | local                      |
| --feature     |    -f   |     ❎      | _string_       | N/A                        |

##### Guardar la configuración de *build* en serverless.yml

También puedes guardar la configuración en el archivo serverless.yml.

```yml
custom:
  smConfig:
    build:
      scope: local
```

#### Ejemplos (Comando build)

##### Compilar todas las características (ámbito local)

```yml
# Compilando todas las características locales
$ sls m build
```

##### Compilar una sola característica (ámbito local)

```yml
# Compilando una sola característica
$ sls m build -f jedi -s local
```

##### Compilar todas las características con ámbito global

```yml
# Compilando todas las características con ámbito global
$ sls m build -s global
```

### Comando deploy

El comando deploy ayuda a implementar proyectos serverless en AWS (utiliza el comando `sls deploy`).

#### Opciones (Comando deploy)

Este comando viene con cuatro opciones:

**--sm-parallel**: Especifica si deseas implementar en paralelo (solo se ejecutará en paralelo cuando se realicen múltiples implementaciones).

**--sm-scope**: Especifica si deseas implementar características locales o globales.

**--sm-features**: Especifica las características locales que deseas implementar (separadas por comas si son varias).

| Opciones          | Atajo |  Requerido  |      Valores     |     Valor predeterminado   |
| ----------------- | :---: | :---------: | --------------- | -------------------------- |
| --sm-parallel     |   ❎  |     ❎      | _true, false_    | true                       |
| --sm-scope        |   ❎  |     ❎      | _local, global_  | local                      |
| --sm-features     |   ❎  |     ❎      | _string_         | N/A                        |
| --sm-ignore-build |   ❎  |     ❎      | _string_         | false                      |

##### Guardar la configuración de *deploy* en serverless.yml

También puedes guardar la configuración en el archivo serverless.yml.

```yml
custom:
  smConfig:
    deploy:
      scope: local
      parallel: true
      ignoreBuild: true
```

#### Ejemplos (Comando deploy)

##### Implementar todas las características localmente

```yml
# implementar todas las características locales
$ sls m deploy
```

##### Implementar todas las características globalmente

```yml
# implementar todas las características globales
$ sls m deploy --sm-scope global
```

##### Implementar una sola característica

```yml
# implementar características globales
$ sls m deploy --sm-features jedi
```

##### Implementar múltiples características

```yml
# implementar características globales
$ sls m deploy --sm-features jedi,sith,dark_side
```

##### Implementar múltiples características en secuencia

```yml
# implementar características globales
$ sls m deploy  --sm-features jedi,sith,dark_side --sm-parallel false
```

### Comando remove

El comando remove ayuda a eliminar proyectos serverless de AWS (utiliza el comando `sls remove`).

#### Opciones (Comando remove)

Este comando viene con cuatro opciones:

**--sm-parallel**: Especifica si deseas eliminar en paralelo (solo se ejecutará en paralelo cuando se realicen múltiples eliminaciones).

**--sm-scope**: Especifica si deseas eliminar características locales o globales.

**--sm-features**: Especifica las características locales que deseas eliminar (separadas por comas si son varias).

| Opciones          | Atajo |  Requerido  |      Valores     |     Valor predeterminado   |
| ----------------- | :---: | :---------: | --------------- | -------------------------- |
| --sm-parallel     |   ❎  |     ❎      | _true, false_    | true                       |
| --sm-scope        |   ❎  |     ❎      | _local, global_  | local                      |
| --sm-features     |   ❎  |     ❎      | _string_         | N/A                        |

##### Guardar la configuración de *remove* en serverless.yml

También puedes guardar la configuración en el archivo serverless.yml.

```yml
custom:
  smConfig:
    remove:
      scope: local
      parallel: true
```

#### Ejemplos (Comando remove)

##### Eliminar todas las características localmente

```yml
# eliminar todas las características locales
$ sls m remove
```

##### Eliminar todas las características globalmente

```yml
# eliminar todas las características globales
$ sls m remove --sm-scope global
```

##### Eliminar una sola característica

```yml
# eliminar características locales
$ sls m remove --sm-features jedi
```

##### Eliminar múltiples características

```yml
# eliminar características locales
$ sls m remove --sm-features jedi,sith,dark_side
```

##### Eliminar múltiples características en secuencia

```yml
# eliminar características locales en secuencia
$ sls m remove  --sm-features jedi,sith,dark_side --sm-parallel false
```
